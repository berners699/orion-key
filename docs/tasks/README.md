# 实施任务与验收记录

按 [需求工作流](../requirements/README.md) 使用 `<需求标识>.md`。计划在实现前填写，结果在验证后填写。简单任务可合并记录，仍需保留必要的验证证据。

## 任务模板

- **需求**。链接需求记录，或直接写明目标、范围和验收条件。
- **现状与影响**。记录入口、复用点及前端、后端、数据库、权限、外部服务和文档的影响。标记不适用项。
- **计划与回滚**。列出有顺序的实施和检查步骤。记录配置、数据库回填、兼容或部署依赖，以及恢复步骤。
- **授权与待确认**。写明需负责人决定的业务规则和数据边界，记录结论。继续推进与这些决定无关的部分。
- **结果与验收**。逐条记录命令或场景、预期、实际结果、退出码、覆盖范围和未完成原因。
- **文档更新**。列出已同步的架构或契约文档，以及留待后续处理的问题。

| 验收项 | 检查命令或场景 | 状态 | 证据与复验条件 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 未运行 | 待填写 |

状态使用“通过”“失败”“受阻”“未运行”或“不适用”。环境阻塞时保留首次失败与重试证据，复验条件应可执行。任务记录只写环境类型和变量名，凭据与真实客户数据不入库。
